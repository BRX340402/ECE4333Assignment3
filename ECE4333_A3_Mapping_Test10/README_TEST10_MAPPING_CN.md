# Test10：测图版（只循迹 + 全量记录 + 画地图）

这一版专门用来扫描赛道、记录数据和画地图。红绿灯、STOP 牌、AI 停车逻辑都**不参与控制**（ESP32 摄像头照常工作，但 UNO 会忽略它发来的识别结果）。
测图完成后要做交通测试，请把 **Test9 的 UNO 和 ESP32 两端都重新上传**：本版的串口波特率（19200）和版本号（UV=40）与 Test9 不同，混用会无法通信。

## 包内容

## 精简了什么
- UNO 删除了：交通状态机、视觉/AI 停车、RGB 灯（FastLED）、超声避障/跟随模式、旧的循迹模式、队友 PD、旧的 Ex3 搜线。
- 保留：网页 Start/STOP/急停、网页方向键手动驾驶、地面阈值和速度设置、陀螺仪 + 轮指令位置估计、超声波前方急停。
- 新的循迹逻辑在 `LineFollower.h`（约 180 行，纯逻辑，可以在电脑上仿真）：
  - **FOLLOW**：中间传感器在线上就前进；中间 + 一侧见黑时轻微修正；只剩一侧见黑时朝那一侧弧线转，超过 150 ms 就原地转。
  - **CROSS**：600 ms 内左右两侧先后都看到黑线（交叉线扫过整排传感器的特征）时，锁住进入时的航向直行 400 ms，不会被交叉线带走。
  - **TURN**：线走到头（急弯）时，朝“最近一次新出现黑线”的那一侧原地转，直到中间传感器重新压线。与进入方向相差约 150° 以上的线（也就是刚走过的那条）不接受，所以不会掉头往回跑。转 200° 还找不到，就反方向再扫一次。
  - **SEARCH**：前面都找不到时，依次 ±45°、±170° 扫，再往前挪一小段重复，最后报 FC=11 停车。
  - 胶带比传感器排还宽（中心时三个都黑）时会自动识别为宽胶带，这时交叉口靠“三个全黑就直行”通过。
- 陀螺仪：量程改为 ±500°/s（原 ±250°/s 在原地转时可能饱和），加了低通滤波，停车时缓慢跟踪零偏。**本版默认开启陀螺仪导航，测图时请保持开启。**



## 第二次实车（run 2）的结论和本版改动
- **D 角向左转**：左侧传感器在直线上读数一直在 550～730 之间跳（车稍微偏、压在胶带边缘），黑线阈值 BL=600 正好落在这个范围中间，所以左侧不停“闪黑”。程序按“最后新出现黑线的一侧”决定转向，于是被噪声带成了左转。
  - 已改：判黑加 **±40 的滞回**（BL=600 时读数要 ≥640 才算黑，<560 才算白）。用这次的数据核对过：滞回后 D 角之前 400 ms 内左侧没有新出现的黑线，会正确向右转。
  - 建议在网页上重新做一次 Sample white / Sample black。这次的数据里白地大约 420～520，黑线大约 760～830，**BL 设在 630～650 左右**更稳。
- **陀螺仪方向反了**：车实际向左转，读数却在减小，程序触发 FC=10 停车。
  - 已改：第一次原地转时如果发现方向相反，程序会自动纠正并继续跑（纠正结果保持到关电）。网页 Gyro 一行会用红字提示。**请在设置里把 Gyro Z sign（GS）改为 1 并保存**，下次就不用再自动纠正。
- **地图比实际慢**：从 C 到 D 的 3.2 m 用了 20 秒，实际约 16 cm/s，旧的速度系数 0.07 只能算出 3.4 cm/s。
  - 已改：速度系数改为 **0.33 cm/s 每 PWM**，地图上的车和实际速度基本一致；跑完完整的直线段后，比例还会再自动微调。
- 修了一个记录 bug：上一版 UNO 程序的样本里，“见黑 / 事件”列一直是 0（一行代码被误放进了注释），地图上的交叉口和转角标记因此不显示。不影响行驶。

## 陀螺仪必须正常（Test10 第一次实车的教训）
第一次实车数据里，`yaw_deg` 和 `gyro_rate_dps` 整场都是 0，说明陀螺仪没有工作。这会导致：
- 小车无法判断转了多少度，转角时识别不出“刚走过的那条线”，所以第二圈在 D 角转错了方向，接着沿原路走了；
- 地图识别不出直线段，距离比例无法校准，网页上的车只沿一条直线、以约 1/4 的速度移动（这就是“图比实际慢”。数据传输本身延迟只有 0.1～0.5 秒）。

本版已修改：
- 你的套件用的是 **GY-521 模块（MPU6050）**：按 ELEGOO 扩展板原理图，接在 UNO 的 A4（SDA）/ A5（SCL），地址 0x68，和程序一致。程序仍会自动识别 MPU6050（0x68/0x69）和 QMI8658（0x6B/0x6A）两种芯片。
- 新增 **I2C 总线恢复**：如果 UNO 在读陀螺仪的过程中被复位（上传程序、拨开关、电压波动），MPU6050 可能一直把数据线拉低，之后全部读数失败，直到断电为止（第一次实车很可能就是这种情况）。现在启动时、以及停车时读数失败，都会先发 9 个时钟脉冲把总线放开，再重新初始化，每 2 秒重试一次。
- 网页“道路测图”区域最上方有一行 **Gyro**：
  - `Gyro OK (MPU6050)` 或 `Gyro OK (QMI8658)`：正常。用手把车向左转，后面的 yaw 应该增大。
  - 红字 `GYRO NOT WORKING (…)`：没找到芯片或读数失败，**Start 会被拒绝**。处理方法：
    1. 看 `IW`：正常的 MPU6050 是 **104**（0x68）。兼容芯片可能是 112、114、152 等，也能用。
    2. `IW=255` 表示 I2C 上没有任何应答：检查扩展板上的 GY-521 小板是否插紧、有没有插偏一排；然后关电，车放平静止，再开电。
    3. 还不行就把这一行完整拍照发给我。
- 每个数据样本里多了 `gyro_ok` 列；陀螺仪不工作时，地图摘要会明确提示。

## 上传前要确认的设置
在 `UNO_Mapping/MapConfig.h`（ESP32 端对应的是 `Config.h`）：
- `LINK_BAUD = 19200` 必须等于 ESP32 `Config.h` 里的 `UNO_LINK_BAUD`。如果通信不稳定，两边都改成 9600，并把 `SAMPLE_MS` 改成 150。
- `CROSS_HOLD_MS`、`PIVOT_PWM` 等循迹参数都在这个文件里，一般不用改。

网页设置里本版**只使用** BL/BH（黑线阈值）、CS（巡航 PWM）、GS（陀螺仪方向）。RA/SA/CT/SC/RS/DS/RP 会被接受（让网页显示“已应用”），但不起作用。Teammate PD 选项会被拒绝。

## 跑车步骤（只用平板，不需要电脑和线缆）
1. 两端都上传后，开关切到 CAM。**上电后保持车静止约 1 秒**（陀螺仪零偏标定）。
2. 把红绿灯和 STOP 牌拿走。前方超声波连续 3 次读到 ≤12 cm 会急停。
3. 平板连接 Wi-Fi `ECE4333_A2_V2`（密码 `12345678`，这个热点没有互联网是正常的），浏览器打开 `http://192.168.4.1`。
   - 平板设置里把“自动锁屏”改成“永不”或尽量长；跑车期间保持这个页面在前台。
   - 页面打开后，**“Road mapping / 道路测图”** 区域就会自动开始记录，不需要按任何记录按钮。
4. 先点 **STOP CAR**。在 Line and search settings 里确认黑白阈值（以前标定过就沿用），Cruise speed 设 **60**，保存，等 UNO 确认。
5. 陀螺仪检查（都在“道路测图”区域最上方）：
   - **Gyro** 一行必须是 `Gyro OK`。
   - 下面是实时读数：大字是累计航向角（左转为正），还有 0～360° 方向、角速度（°/s）和一个跟着车头转的指南针（车停着时每秒更新 5 次，跑车时 10 次）。
   - 车停稳后点 **Zero + recalibrate gyro 陀螺仪归零**：小车会用 1 秒重新测量陀螺仪零偏，然后把航向和位置清零。这 1 秒内不要碰车，完成后提示 “Zeroed ✓”。车在跑或没停车时会被拒绝。每次 Start 也会自动清零位置和航向（但不重测零偏）。
   - 车静止时角速度应该接近 0（±0.3 °/s 以内），航向应该基本不动；一直在漂就再点一次归零。
   - 用手把车**向左**（逆时针）转约 90°，读数应该增加约 90。如果变小，改 Gyro Z sign（GS）并保存。陀螺仪导航在本版默认开启，不用勾选 “Optional gyro navigation”。
6. 把车放在 **C 点**（左下 60° 角），车头沿线朝 STOP 牌方向，点 **Start continuous run**。
7. 车跑的时候，“道路测图”区域会每 1～2 秒更新一次地图：蓝线是轨迹，红圈是车现在的位置，状态栏显示收到的样本数、是否有丢失、车当前的状态。
8. 跑 1～2 圈后点 **STOP CAR**。
9. 下载（每个文件一个按钮，逐个点）：
   - **Download data CSV 数据**：全部采样数据（最重要，每次都要下载）
   - **Download all lines 全部原始数据**：UNO 发出的每一行原文
   - **Map PNG 地图图片**、Map SVG、Segments CSV 分段表、Track points CSV 轨迹点、Summary TXT 摘要
   - iPad 的 Safari 会先问“是否下载”，文件保存在“文件”App 的“下载”文件夹里；安卓保存在“下载”目录。
   状态栏显示 “downloaded” 说明已经下载过；显示 “NOT downloaded yet” 说明有新数据还没下载。
10. 想重新开始时，点 **Delete recording from tablet** 清除平板上的旧数据（会先提醒是否已下载）。

**中途出问题：**
- 刷新或不小心关掉页面：数据保存在平板浏览器里，重新打开 192.168.4.1 后会自动恢复，并从断点继续补齐（小车缓存约 3 分钟）。
- 状态栏出现 “LOST n”：说明断开超过约 3 分钟，丢了 n 行。
- 车冲出去或停住：先 STOP CAR，看网页上的 FC 和 ES（见下方故障对照），把车放回 C 点重新 Start。每次 Start 是一个新的 run，“Map of” 下拉框可以选择查看哪一次。
- 可以用网页方向键把车手动开回线上，手动驾驶期间同样在记录。
- 平板浏览器存储大约够 20 分钟的数据，超过时状态栏会提示“storage full”，这时先下载，再清除。

## 地图怎么看
- 灰色粗线是作业图纸上的参考赛道；彩色线是重建的轨迹（蓝 = 循迹，橙 = 交叉口锁航向，红 = 转角，紫 = 搜线）；黑点是三个传感器全黑的位置（交叉口）；青色方块是识别到的转角；绿点是起点 C。
- 摘要里重点看：
  - `segment order seen` 应该是 `C-O-D > D-E > E-O-A > A-B > B-C`。带 `(?)` 的地方是走错或掉头的位置。
  - `laps completed` 和 `closure error`：跑完的圈数，以及回到起点时的位置误差。
  - `measured speed factor`：实测的 PWM→速度系数。
- 分段表就是道路地图：每一段直线的实测航向和长度，与图纸值对比。
- **Track lengths 赛道实测长度**：用卷尺量出每段直线（转角到转角）的长度后填进去并保存，地图比例会更准。A-B（43 cm）和 B-C（125 cm）是按图上角度推算的，一定要实测。

算法：只用陀螺仪航向，按 C-O-D → D-E → E-O-A → A-B → B-C 的顺序和转角角度识别直线段；用两端都有转角的完整段求距离比例；拟合并扣除陀螺仪漂移；每跑完一圈，把终点误差按距离分摊、闭合到起点。

## 电脑工具（可选）
`PC_Mapping/` 里的 `map_logger.py` / `draw_map.py` 做的事情和网页一样。网页下载的 `map_samples_*.csv` 也可以直接用 `python draw_map.py map_samples_xxx.csv` 处理。

## 新数据格式（每一行 UNO 输出都被保存）
N230（跑车时 10 Hz，停车时 2 Hz）：
`{"N":230,"d":[序号,UNO时间ms,L,C,R,左PWM,右PWM,角速度×10,累计航向×10,距离mm,X cm,Y cm,超声cm,状态,事件]}`
- 状态 = 模式×16 + 循迹状态（1 FOLLOW，2 CROSS，3 TURN，4 SEARCH，5 FAIL），例如 97 = 自动行驶 + FOLLOW。
- 事件位：1/2/4 = 本周期内左/中/右见过黑，8 = 三个同时黑，16 = 进入 CROSS，32 = 转角，64 = 搜线，128 = 急停。
- 距离和 X/Y 用的是 PWM 模型（0.07 是占位值），比例由 draw_map 修正。

N221 保留原有字段（网页正常显示），新增 MQ（已采样数）和 MD（UNO 端因串口忙而覆盖的样本数）。

## 故障对照
| 现象 | 含义 / 处理 |
|---|---|
| FC=10 | 陀螺仪方向反了，改 GS |
| FC=11 | 搜线全部失败；看 map.svg 停在哪里，通常是速度太快或胶带太窄 |
| FC=14 | 搜线时前方有障碍 |
| ES=1，ER=2 | 超声波连续 3 次读到 ≤12 cm；拿开障碍后清除急停，再重新 Start |
| 测图状态栏显示 LOST n | 断线超过约 3 分钟，ESP32 缓存被覆盖 |
| MD > 0 或 UNO seq gaps > 0 | 串口太忙；改回 9600 的话把 SAMPLE_MS 改大 |
| 网页显示 UNO VERSION MISMATCH | 有一端没有上传 Test10 |
| Gyro 一行显示红字 / Start 被拒绝 | 陀螺仪没识别到或读数失败；关电后静止开机，仍不行把 IW、IQ 数值发给我 |

## 验证情况（诚实说明）
- UNO：用 avr-gcc 14.1 + Arduino AVR core 1.8.6 真实编译通过，Flash 31024/32256，静态 RAM 1574/2048（Arduino IDE 自带的 gcc 7.3 编出来约小 5 KB；原 Test9 在 gcc 14 下会超出，但在 IDE 里能放下）。Arduino IDE 自带的 avr-gcc 7.3 生成的代码会更小：原 Test9 在 gcc 14 下超出 4868 字节，但在 IDE 里能放下。

- 循迹逻辑仿真（按图纸的 8 字赛道，含电机死区/不对称、陀螺仪漂移/比例误差、传感器噪声）：
  - 陀螺仪方向设反：96 组中 95 组在第一次转弯时自动纠正并跑完两圈。
  - 网格测试（陀螺仪开启）104/108 跑完两圈；失败的 4 组都是胶带比传感器间距窄。
