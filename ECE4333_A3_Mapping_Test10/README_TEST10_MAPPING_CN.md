# Test10：测图 + 遇红停车版

功能：循迹跑 8 字赛道、记录全部数据、在平板网页上实时画地图；可选“遇红停车”（红色像素达到 RP → 停车 → AI 判断 STOP 牌：是就停 3 秒再走，不是就等绿灯）。
**UNO 和 ESP32 两端都要上传本包的程序**（串口 19200、版本号 UV=40，与 Test9 不通用）。

## 存储空间（UNO）
用和 Arduino IDE 相同的 avr-gcc 7.3 编译：**Flash 27476 / 32256（85%），RAM 1496 / 2048（73%），局部变量可用约 550 字节**（加了路线提示后）。
（上一版在你的 IDE 中是 Flash 76%、RAM 75%。这一版加了遇红停车，Flash 多用约 2 KB；同时把样本缓冲从 10 条减到 6 条，RAM 反而少用约 100 字节，不会再出现 “Low memory” 警告。我的工具编译原版 Test9 比你的 IDE 多算约 400 字节，所以你那边的数字会略小。）

## 遇红停车（Stop on red）
1. 摄像头页或行驶页看 **Red pixels now**：把红色目标（红灯 / STOP 牌）放在希望停车的位置，记下像素数，填入 **RP**（比如读数 200 就设 170～190）。
2. 勾选 **Stop on red 遇红停车**，自动停车并保存，等“UNO confirmed”。摄像头设置里 STOP AI 和红绿识别都要开着。
3. 运行中：循迹在直线上（不在转角或搜线中）时，红色达到 RP → 停车，状态显示 `RED: CHECKING STOP`，ESP32 开始做 STOP 牌 AI 识别：
   - 2 次识别为 STOP → `STOP SIGN 3 s`，停 3 秒后继续；
   - 2 次识别不是 STOP（红灯）→ `WAIT FOR GREEN`，看到 2 帧绿色（且没有红色）后继续；
   - 20 秒内 AI 没给出结果 → 也按红灯处理，等绿灯。
4. 重新出发后，同一个红色目标会被忽略，直到连续 3 帧看不到红色为止，不会反复停在同一块牌子前。
5. 取消勾选 = 纯测图模式，红色被忽略。停车期间地图上的轨迹显示为粉色。

## 跑车步骤
1. 车放平，开电后**静止 1 秒**（陀螺仪零偏）。平板连 Wi-Fi `ECE4333_A2_V2`（密码 `12345678`），打开 `http://192.168.4.1`，关掉平板的自动锁屏。
2. **设置页**：Sample white / Sample black → Apply（按你的数据，白约 420–520，黑约 760–830，BL ≈ 630–650）。**Gyro Z sign 选 “Positive raw Z = left”（GS=1）**，保存。
3. **行驶页**：Gyro 显示 OK → 车停稳点“陀螺仪归零” → 用手向左转约 90°，航向应 **+90 左右**。设好遇红停车和速度（CS 55–70）。
4. 车放在 **C 点**（左下 60° 角），车头朝 STOP 牌方向，点 **Start**。
5. **地图页**实时显示轨迹。跑完点 **STOP CAR**，再逐个下载（至少下载 **Download data CSV 数据**）。iPad 的文件在“文件”App →“下载”。
6. 页面刷新或断线都不会丢数据：平板里有存档，小车会缓存约 3 分钟的数据，重连后自动补齐。

## 第三次实车（两圈）结果
- 陀螺仪方向在第一个转角**自动纠正**后，两圈都按 C-O-D → D-E → E-O-A → A-B → B-C 顺序跑完，11 段直线全部识别。
- 各段航向与图纸相差在 3° 以内；第一圈小车自己算的距离约 **859 cm**（图纸 859.6 cm），说明速度系数 0.33 是准的。两圈的闭合误差约 18 cm / 22 cm。
- 为此修改了画图算法（网页和 Python 同步）：
  - 去掉原地转弯结束时航向还在收敛的短“过渡段”（之前直线因此被切碎）；
  - 有完整圈时，用“整圈距离 / 859.6 cm”来定比例，比按单段计算更准（这次比例 ×1.00）。

## 第四次实车（2026-10-14）：第一个角又左拐
CSV 里有三次运行：
- **第一次**：数据里没有事件位，距离按旧速度系数（约 0.07）计算，说明当时 UNO 上还是**旧程序**（之后 UNO 重启，时间归零）。到 D 角时它向左原地转，但陀螺仪读数向右走（方向反了），旧程序不会自动纠正，于是报故障停车。
- **第二次**（新程序）：D 角正确右转，接近跑完两圈。
- **第三次**（新程序）：先在 91 cm 处遇红停了 6.4 秒后继续（遇红停车起作用了），到 D 角（305 cm）又**向左**转了。

第三次的原因：快到 D 角时，车稍微偏向线的右侧，左传感器先压到胶带；接着右传感器看到黑（被当作十字交叉）；在 60° 尖角顶点，三个传感器同时黑，然后**左传感器又重新见黑**；线结束时，按“最近新出现黑线的一侧”规则就选了左。第二次运行时右侧是最后出现的，所以转对了。这完全取决于车压线的偏移，是偶然的。

修复（`LineFollower.h` 路线提示）：赛道固定，从 C 点朝 D 出发，所以每条直线的方向和长度都已知（C-O-D 0°，D-E −137°，E-O-A −240°，A-B −210°，B-C −120°），下一个角往哪边转也已知（D 右、E 右、A 左、B 左、C 左）。
- **只在传感器分不清时使用**：线结束前左右两侧都见过黑；
- 而且只在一条直线的**最后 30%** 使用（按里程计算），所以经过十字路口和直线中间的晃动仍然按传感器判断；
- 当前在哪条直线：转完弯后，学到的线方向接近下一条直线、且已经走完当前直线一半以上时，前进到下一段；
- 地图页状态栏显示 `route: on C-O-D, next corner D RIGHT`，可以看它是否跟得上。
- 换赛道或换起点时，把 `MapConfig.h` 中的 `ROUTE_HINT` 改成 `false`。

## 循迹逻辑（`LineFollower.h`）
- **FOLLOW**：中间传感器在线上就前进；中间 + 一侧见黑时轻微修正；只剩一侧见黑时朝那一侧弧线转，超过 150 ms 就原地转。
- **CROSS**：600 ms 内左右两侧先后都见黑（交叉线的特征）时，锁住航向直行 400 ms。
- **TURN**：线走到头时，朝“最近新出现黑线”的一侧原地转（PWM 100）；与来路相差 150° 以上的线不接受（不会掉头）；转 200° 还没找到就反向再扫。
- **SEARCH**：±45°、±170°，往前挪一小段再重复，最后报 FC=11 停车。
- **路线提示**：两侧都见过黑、分不清方向时，在直线末段按固定路线决定转向（见上一节）。
- 判黑有 ±40 的滞回；第一次原地转时如发现陀螺仪方向相反，会自动纠正（保持到关电，网页红字提示改 GS）。

## 数据格式
N230（跑车时 10 Hz，停车时 5 Hz）：`{"N":230,"d":[序号,UNO时间ms,L,C,R,左PWM,右PWM,角速度×10,累计航向×10,距离mm,X cm,Y cm,超声cm,状态,事件]}`
- 状态 = 模式×16 + 8×(陀螺仪正常) + 循迹状态（1 FOLLOW，2 CROSS，3 TURN，4 SEARCH，5 FAIL，6 红色停车）。
- 事件位：1/2/4 = 左/中/右见过黑，8 = 三个同时黑，16 = 进入 CROSS，32 = 转角，64 = 搜线，128 = 急停。
- N221（1 Hz，交通状态变化时立即发送）：TS 交通状态（2 循迹，4 红色识别中，5 等绿灯，6 STOP 停车，7 交叉口，8 故障），ID 为 AI 请求号；另有 IM/IW/IQ/IB（陀螺仪芯片诊断）、CB（归零中）、GL/GF（陀螺仪方向自动纠正）、SG（路线段 0–4 = C-O-D、D-E、E-O-A、A-B、B-C）。为了不超过 UNO 的发送缓冲区，删除了没有用到的 KX/KY/KH/GC/PD。

## 故障对照
| 现象 | 含义 / 处理 |
|---|---|
| FC=10 | 自动纠正后陀螺仪方向仍然相反；检查 GS |
| FC=11 | 搜线失败（速度太快、胶带太窄、车被拿起） |
| FC=14 | 搜线时前方有障碍 |
| E-STOP（ER=2） | 超声波连续 3 次 ≤12 cm；移开障碍 → Reset → Start |
| Gyro 红字 / Start 被拒绝 | 陀螺仪没识别到（IW=255 表示 I2C 没有应答）：检查 GY-521 是否插紧，关电后静止开机 |
| 停在红色前不走 | 状态是 WAIT FOR GREEN：AI 判断不是 STOP 牌，需要绿灯；或者 RP 设得太低，被背景中的红色触发 |
| 测图状态 LOST n | 断线超过约 3 分钟 |
| UNO VERSION MISMATCH | 有一端没上传 Test10 |
