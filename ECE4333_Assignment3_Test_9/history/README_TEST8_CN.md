# Test8：断连停车排查及左弯接线修复

同时上传本包 UNO 和 ESP32，UNO UV=38。使用与 Test7 相同的板卡/库设置，上传后切 CAM。

## 找到的问题与修复
1. Test7 自主模式 M=6 已绕过遥控心跳超时，网页 poll 失败也不发送 STOP。但是 ESP32 setup 在每次重启时发送 N100，导致仍运行的 UNO 被强制停车。Test8 改为 N214，只清除相机帧序号去重状态，不修改电机、运行模式、急停或交通状态。ESP32 单独重启不再因此终止自主运行。网页识别到 esp_ms 回退会提示重启。
2. 这不证明用户每次断连都是 ESP32 重启。若 UNO 也掉电/复位，小车仍会停车，需要重新启动；本版不会自动重启掉电后的车。供电/复位原因仍需串口记录或时间戳判定。
3. 原搜线只确认静止中央黑线60ms，就清空搜线状态并恢复巡航速度。现在先确认60ms，再以不超过PWM45低速接线220ms；成功后下一轮控制才恢复设定速度。期间丢线保留原搜索阶段及方向，不立即重启向右扫描。
4. 原默认控制器在左+中传感器同时见黑时优先直行。现在左+中时左轮减半，右+中时右轮减半，向线修正。
5. 刚追踪到左/右偏线后，180ms内短暂全白，先继续原修正方向，超过窗口才启动完整右120/左360搜线。没有可信方向历史时不盲目新增前冲。
6. 两侧黑、中间白不再作为搜线成功条件。正常行驶的两侧同时黑按宽区域处理，最多600ms保持进入方向，之后搜线。交叉口的 CROSS 专用控制继续保留。
7. UNO发送缓冲与ESP32接收上限同时从288扩大到352字节，N221周期400改600ms，降低9600波特串口占用并增加长遥测包余量。这是通信稳健性调整，尚无现场证据证明用户断连由包长造成。

## 怎样使用
- 先使用默认巡线控制器（不是 Teammate PD），保持此前可用的巡航60、减速30、CIF设置；不用为了此修复重新标定相机。
- 陀螺仪导航仍默认关闭。搜线角度关闭时为定时估算，开启后才是陀螺仪测量角度。
- 主界面 Start continuous run 启动自主模式 M=6。手动箭头与其他旧模式仍保留通信超时停车，这是手动控制行为。
- 扫描记录选项及每次独立CSV保留。记录仍需网页在线，断线期间没有传感器数据可补录。
- STOP、急停、红灯等待、障碍物急停、真实搜线失败继续有效；更改相机设置/标定等显式操作也可能停车，不应运行中操作。

## 再次停下时怎样区分
读取 /traffic-status 或保存扫描CSV，不要只看“Disconnected”字样：

| 现象/字段 | 解释 |
|---|---|
| 浏览器请求失败，或 age_ms 大 | 通信/遥测过期，不能据此知道电机是否停止 |
| esp_ms 回到较小值，uno.UT仍持续增长 | ESP32重启，UNO未重启 |
| uno.UT、uno.RN回到启动时的小值 | 提示UNO复位；需结合完整前后记录排除计时回绕 |
| M=0 | UNO已处于停止/待机，可能为显式停车、急停或复位后的状态 |
| ES=1、ER=2 | 测到前方近障碍，触发急停 |
| TS=5或6 | 等绿灯或STOP停留，不是通信超时 |
| TS=8、FC=9/10/11/14 | 搜线超时/航向符号错误/搜索耗尽/前方阻塞 |
| M=6、TS=2、SE=1 | 正在搜线；短暂零PWM可能是候选黑线确认 |

如果仍重复断连，提供停下前后CSV或 /traffic-status 的完整JSON；由时间戳、模式和故障字段确定实际原因，不把网页提示当成停车指令。

## 验证与范围
新增回归测试覆盖左+中转向、短时丢线、接线失败保持向左搜索、低速成功交接、两侧黑假接线、ESP32启动命令与序号重置不改变运动状态。原交通、陀螺仪开关、CSV等测试继续通过。
ESP32只有主机接口语法检查，没有目标板编译/实车验证。接线时间和PWM上限是初始参数，并非已证明适合所有轮胎/电池/赛道。
本次没有更改红/绿/STOP判定规则；此前“任意红色覆盖RP阈值”的已知问题仍存在。

实际UNO AVR编译通过：Flash32106/32256字节，静态RAM1353/2048字节，剩余695字节用于栈及局部变量。Flash仅余150字节；不同库版本可能改变大小，请使用包内配套库。
