- 勾选/速度修改自动停车保存；不自动恢复运动。

# Assignment 3 V13 — UNO CAM 通信与内存修正

本次**只需重新上传 UNO_Assignment2/UNO_Assignment2.ino**，整个同名文件夹必须一起解压使用。ESP32 代码与 V12 完全相同，不需重新上传 ESP32 或更换模型库；相机网页仍显示 V12，这不是上传失败。

## 为什么这次修改 UNO

用户编译结果：Flash 31586 / 32256 字节；静态 SRAM 1558 / 2048 字节，剩余 490 字节供栈与堆使用。原 command() 在每一条 CAM 报文中建立 StaticJsonDocument<384>，该局部对象及其他局部变量、调用栈会使用编译输出没有计入的剩余 RAM。384 字节只是 JSON 文档的容量，实际对象还有管理开销。这构成具体的栈空间风险，与接入相机报文后异常相符，但没有实机栈跟踪，不能断言它是唯一原因。

Flash 的 97% 表示程序存储接近上限；它本身不代表 UART 一定失联。

## 改动

- 移除 UNO 对 ArduinoJson 的依赖及其 384 字节局部文档。IntegerCommand.h 仅解析现有协议需要的平面整数 JSON，不使用堆或文档数组。
- 协议键名使用 PSTR 放在 Flash，不常驻 SRAM。
- RX 缓冲由 192 缩为 160 字节，仍容纳当前 ESP32 发出的所有报文；超长或破损报文丢弃，并在下一个左大括号恢复。
- 每次 RX 最多处理 64 字节，避免持续输入占住整个 loop；在传感器操作前后补充 RX 处理机会，提前泵送遥测。
- 严格检查整数范围、重复字段和消息结构，保留原有停车、超时、STOP 和交通灯规则。串口仍为两端一致的 9600 波特率。
- N221 状态增加 UV=13（UNO 固件版本）、FR（采样时栈/堆之间的 RAM 空间估计，字节）、UT（UNO 运行毫秒）。FR 不是最深栈峰值测量，不代表最低历史剩余 RAM。

## 使用与确认

选择 Arduino UNO 编译和上传新版 UNO 草图；按套件原流程切换 Upload/Cam 开关。确认相机网页的 UNO 状态恢复。可以打开 http://192.168.4.1/traffic-status 查看 uno 内 UV=13、FR、UT；若连续读取时 UT 反复回到较小值且没有主动复位，可继续排查 UNO 重启。

本版没有 ESP32/AVR 目标编译器，因此不能给出新的实际 Flash/SRAM 占用百分比。请以 Arduino IDE 重编译结果为准。建议先让小车停着确认连接稳定，再测试运动。

- 删除未使用的旧独立网页、旧常量和无效缓存变量。V11 本来就未执行人脸识别，所以不能把相对 V11 的性能提升归因于删除人脸。

## 画质与验证限度

主机语法、网页交互、相机启动参数、缓冲复用/隔离、三类标定和预览失败恢复检查已通过，见 VALIDATION.md。主机模拟不能证明真实相机驱动、任务时序或模型的板上表现。尚未测量 V12 的 FPS、识别耗时、编译大小、峰值内存，也不能承诺黄绿偏色或雪花已消失。

Camera diagnosis 中可读取运行时间、最近帧龄、累计帧数及采集错误数。采集错误统计能发现取帧失败、尺寸异常或缓冲分配失败，但不检测 JPEG 内部的视觉噪点；错误数为零不等于画面没有雪花。
