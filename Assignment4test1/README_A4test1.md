# A4test1 修改与验证

原版来自分支 A4_exclude_TargetFollow，commit c6cc85da46c44dc40d602c408d944d940a910f8f 的 ECE4333_A3_Test13。assignment4 与该目录逐文件一致。

## 修改
- 交通停车暂停/恢复超车阶段计时，避免 STOP 停车消耗转向超时时间。
- 超车启用时要求陀螺仪有效且启用导航；进行中的超车丢失陀螺仪进入失败并停止。无陀螺仪时启用超车会保持停车，请关闭超车选项后再单独测试普通巡线。
- 转向超时当次输出归零；超车失败后统一归零。
- JOIN 要求中间传感器连续检测黑线至少 150 ms 且航向误差小于 20 度；删除超时后任意传感器见线就判成功的兜底。
- 日志优先显示交通停车；网页保留被交通停车中断的同一次绕行记录。
- 等待障碍离开单独标记 wait cleared，不计成功；只有记录到 OUT→PASS→RETURN 并恢复巡线/路口状态才计成功。采样丢失仍可能导致统计漏报，不能替代人工实测。
- 重建 TrafficPage.h 与 TrafficPageGzip.h；增加暂停、回线、超时和统计回归测试，测试脚本启用 pipefail。
- 固件 UV 保持 43，因为未改变通信字段格式；务必配套使用本目录的 UNO 与 ESP32。

## 验证结果
主机 UNO 协议测试（含启用目标跟随的编译配置）、跟随/路线测试、ESP32 桩语法检查、网页地图测试与新增回归测试通过。
巡线仿真 103/108；压力仿真 388/400；反向陀螺仪自动校正 96/96。
绕行仿真：有空间 49/80（原版 50/80）；静态半径≤8cm 35/48；无空间 51/64（原版 58/64）；144 场景仍有 1 次接触障碍。
严格回线判定没有提高现有仿真的总体完成率，需继续分析失败场景并实车调参。该版本是安全逻辑与统计修正版，不是已解决完整 A4 的最终固件。
详细日志：validation/A4test1_host_tests.log。其他原有 validation 文件属于上游历史结果。
未做 AVR/ESP32 目标板编译、Flash/SRAM 检查、烧录或实车测试。未实现移动目标速度估计、侧向障碍边界跟踪或独立实际轨迹测量。

## 测试与实车顺序
在具有 g++、Python 3、Node.js 与 Bash 的环境运行 bash tests/run_tests.sh。
先在 Arduino IDE 完成两个目标板的编译和容量检查，再架空车轮测试交通停车和陀螺仪失效；之后低速测试静态障碍、稳定回线及 STOP 与超车联合行为。
