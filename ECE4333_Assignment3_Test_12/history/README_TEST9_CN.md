# Test9：右扫范围与红色像素动作阈值

必须同时上传本包 UNO、ESP32，UNO版本 UV=39。保持之前可用的开发板和配套库设置，上传完切CAM。Test8的断连/接线改动及Test7扫描CSV功能保留。

## 红色阈值为何一直无效
ESP32原来已经用 redActionTriggered() 判断 红色Pixels >= RP，并把结果通过N204.R发送。UNO却把N204.R与N203的“任意红色”合并，再交给交通状态机；小红块也会触发VERIFY。之前版本确实遗漏了这个错误。

本版修复：
- TRACK行驶中的停车/减速只由N204.R（达到RP的红色）触发。
- N203仍控制红色指示，并在已经停车等待红/绿判定时阻止背景绿色误放行；它不再触发新的停车或污染缓存red状态。
- 设RP=170：有效检测帧的Red Pixels为169时继续TRACK，为170及以上时进入VERIFY。
- 勾选Stop on red时进入VERIFY即请求零PWM；未勾选时按原模式以Reduced speed靠近，保留原标定距离逻辑。
- 停车后红色变小不会自动放行；仍需STOP确认或有效绿灯确认。两帧累计STOP与原有绿灯规则保持。
- RP=0表示不增加动作面积限制，并不取消检测器自身最小像素数要求；没有检测到红色不会停车。
- 修改设定会先停车。等待UNO confirmed后再按Start。比较网页Red Pixels，不要比较框宽width或标定宽度。
- 判断发生在下一次有效识别结果到达时；本次并未消除相机处理和串口传输延迟，不能保证物理上零延时停车。

## 右侧角度
网页、ESP32参数校验、UNO参数校验及执行层上限均从120扩大到360度。
默认右扫180度、反向左扫360度，再向右返回180度。升级时对既有右120且左>=180配置迁移为右180，其他自定义值保留。
可自行停车后设置：RA=180/240/300/360；SA必须>=RA且<=360。比如RA=360、SA=360时返回段为0度。
网页显示当前保存的RA/SA，不再固定写120。

陀螺仪导航仍默认关闭：此时角度是按电机运行时间估算，电池/摩擦会影响实转角度。只有开启且陀螺仪正常时才按实测角度结束。启用前静止开机并验证左转YA增加、右转减少。
陀螺仪启用时仍保留接近反向线路（相对进入方向约150～180度）的拒绝接线机制；扫描可完整旋转，但不会把反向线当作正确前进路线。

## 使用建议
先保留已验证的巡航60、减速30、CIF；右扫180、左扫360、RP170。勾选Stop on red，保存并确认后启动。若需更大的实际右扫范围再增大RA；不要在行驶中改设置。
扫描日志中 objects.red.pixels、settings.RP、uno.TS、uno.PL/PR 可用于对照动作。网页录制仍需要联网，断线数据无法补录。
