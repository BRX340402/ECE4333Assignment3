# Test7：可选路线扫描与传感器表格

## 这次做什么
- 删除网页中的地图坐标输入、参考坐标轨迹输入、手动位置校正，以及 ESP32/UNO 的 N209 位置校正命令。
- 主界面增加可选路线扫描。每次扫描一张独立 CSV 表格，可用 Excel 打开；网页显示最近20行摘要，下载包含本次全部记录及所有接口字段。
- 保留 Assignment 要求的轮指令运动学预测、陀螺仪融合估计、急停、交通灯与 STOP 控制。扫描仅负责收集经过路线的数据，不执行目标坐标导航。
- 新增超声波、电池等 N210 数据到统一状态接口；补充 N210 的 UNO 时间戳 UT 和角速度 GR10。
- 陀螺仪参与控制仍默认关闭。右120度、反向左360度搜线逻辑沿用 Test6；关闭陀螺仪控制时实际角度为定时估计。

## 使用
1. 同时上传本包 UNO_Assignment2 和 ESP32_Assignment2（UNO版本号 UV=37），上传后切 CAM。库文件见 Arduino_Libraries。相机保持此前 SVGA 初始化设置。
2. 开机保持小车静止，完成陀螺仪零偏采样。放在交通灯起点，车头朝起始行驶方向。
3. 连接小车热点（ECE4333_A2_V2，密码12345678），打开 http://192.168.4.1 。停车后保存地面阈值、巡航速度、减速速度及交通模式，等待 UNO confirmed。
4. 勾选主页面“Record a separate route scan when Start is pressed”，点击“Start continuous run”。每次 Start 清零局部位置和航向。网页收到 UNO 新运行编号后才显示已启动。
5. 让小车按循迹逻辑跑完两个环和交点。你确认所需路线均已走完后，点击“Finish scan and stop car”。只有收到新鲜的 OFF 和左右 PWM=0 反馈后才标记完成。
6. 点击“Download selected CSV”。本次文件名为 route_scan_时间戳_序号.csv。多次扫描通过 Scan session 选择，各次数据不会混在一起。把每次 CSV 原文件发回来，下一步再绘图与定位分析。
7. 不勾选扫描时，Start 只启动原有自动运行。普通 STOP/急停会停车，但不自动宣称路线扫描完整；仍可导出当时的部分数据。

## 记录范围与限制
- 记录所有当前状态接口暴露的传感器/估计/识别/设置字段；不是每个硬件内部采样都被上传。网页通常每次请求完成后间隔500ms轮询；N221约400ms，N210约1000ms，串口占用及识别会导致实际间隔变化。
- 这是网页端采集，必须保持页面打开、电脑连接小车热点且不休眠。Wi-Fi断开不会终止自动行驶，但未收到的数据无法补录；CSV用 connection_gap 标记请求失败，旧缓存用 fresh/new 标志区分。重连后继续记录。
- 每页最多5次扫描，每次最多40000行。满额停止记录并标记 incomplete，不会因此停车。刷新、关闭或崩溃会丢失未下载记录；请及时下载，不能把离页提醒当成持久存储。
- 若结束扫描时通信失败，网页不会声称停车成功；仍保留记录和部分 CSV 下载。恢复连接后重新结束；必要时使用物理停机。
- 程序尚不能自动判断走遍所有路径。交叉点可能多次经过，回到近似原点也不能证明全覆盖，因此本版由操作者确认路线完成。
- 已读取的惯性量为陀螺仪Z轴角速度及其积分航向；没有记录加速度三轴/陀螺仪X/Y、相机原图或编码器实测轮速。不得把缺失项当成零值。
- X/Y 是 PWM速度模型估计，非真实定位；参数尚需标定。扫描没有开启基于已知地图的相机位置校正。真实位置、实际轨道长度和实际平均速度仍需外部测量。

## Assignment 核对
已重新核对 Assignment 3 与 Score 表：任务要求 figure-eight循迹、急停、运动学预测、陀螺仪/相机融合、状态与数据记录、视觉目标跟随；没有要求输入目的地坐标。
本版删除的是手动地图输入与校正界面，并保留预测/融合估计与数据。扫描表是后续绘图、相机地标校正和比较实验的输入，不代表所有 Assignment 评分项已完成。地标位置融合、实际轨迹对比和视觉目标跟随仍需要单独验证/完善。
评分表要求红灯停车，因此正式演示应启用红色停车模式；仅减速不符合该项。沿用 Test6 交通决策，没有在本次改动中修复此前确认的“任意红色可覆盖 RP 阈值”问题，像素阈值不能视作可靠停车门槛。
