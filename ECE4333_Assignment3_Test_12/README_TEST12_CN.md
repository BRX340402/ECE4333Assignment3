# Test12：扫描测试直接启动

UNO 和 ESP32 都要更新；UNO UV=42。本说明替代历史 Test10/Test11 的强制验证启动步骤。

## 直接启动
1. 上传两块板的配套代码，硬件开关切回 CAM。
2. 开机时小车静止放平，让已有自动陀螺仪初始化完成。
3. 连接 Wi-Fi，打开 http://192.168.4.1 。默认 Survey。
4. 将车放在右下角 60° 弯道驶出后的黑线上，车头朝 STOP sign。
5. 点击 Start autonomous run，直接发送速度、循线阈值、陀螺仪符号、五个转角和启动命令。不必先点击校准、方向验证、地面采样或逐项确认。

Survey 仍忽略红绿灯与 STOP 对行驶的干预，依次完成五个弯道后停车；预录地图及设备日志与 Test11 相同。地图未标角度仍是可调整估计值，不保证实车一圈成功。

## 取消了哪些启动门槛
Survey 的网页、ESP32 与 UNO 不再要求：
- 完成人工陀螺仪校准或左右方向验证；
- GY/GN/IV 状态通过后才发送启动；Survey 启动时自动打开 gyro navigation；
- UNO 设置回执和逐项路线修订号确认；
- PSRAM 缓存可用/未满才允许启动；
- 红绿灯/AI已启用、相机色条已关闭才允许 Survey 启动。

路线角度与 PWM 的基本输入范围检查保留，防止发出无效值。已有运行必须先 STOP；锁存急停也需要解除。网页依然需要能连接到 ESP32 才能发送命令。模式0/2的交通运行仍沿用原来的验证条件；本次直接启动只用于你当前的 Survey 扫描测试。

## 保留的陀螺仪操作
在 Sensor setup 中可随时选择（停车状态下）：
- Calibrate stationary bias：重新采集静止零偏，约0.5秒保持静止。
- Zero heading / position：当前航向和位置归零，不重新采集偏置。
- Gyro Z sign：需要时修改方向符号。

每次 Start 仍会自动将航向/位置归零。按钮校准和归零不再是启动前必做事项。左右验证按钮仍可用于自愿诊断，但 Survey 不以结果作为启动条件。

“取消验证”没有把故障数据伪装为有效数据：陀螺仪读数真正不可用时，运行控制仍可能立即报 FAULT8；丢线扫描失败、超过角度边界、近障碍与急停也仍会停车。此时请看具体故障原因，不是网页的校验流程阻止启动。

## 日志
ESP32 PSRAM 中最多1MiB记录。Wi-Fi断开仍继续采集；掉电或ESP32重启会丢失。没有可用缓存或缓存满时，车也能启动，但 Device log 会显示容量0或Dropped；这次数据可能缺失。停车后等约2秒，点击 Route & survey → Download device data as CSV，下载后再关电。不要把未确认的命令当作已执行，按CSV中的UNO状态判断实际运行。

## 验证
Arduino AVR Boards 1.8.6 / Servo 1.2.2 / FastLED 3.2.10：
- UNO Flash：32194 / 32256 bytes。
- 静态 RAM：1358 / 2048 bytes，余690 bytes供栈和局部变量使用。

实际 UNO 编译通过；测试覆盖Survey无验证启动、保留的交通模式门槛、急停、路线恢复、原交通识别、日志和网页模拟交互。ESP32通过主机语法检查，未完成ESP32目标板编译或实车验证。

运行 tests/run_test12.sh 可复现主机检查。旧说明在history，当前启动步骤以本文件为准。请使用包内配套库，UNO Flash余量仅62 bytes。
